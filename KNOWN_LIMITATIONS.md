# Known Limitations & Simulator Model Boundaries

To maintain academic honesty and engineering clarity, students and instructors should note the following boundaries:

1. **Browser Sandbox vs. Physical Host Telemetry**: Standard web applications run inside a browser security sandbox and cannot read physical voltage levels, embedded-controller firmware states, CPU package temperatures, cache line tags, or DRAM refresh cycles from the user's laptop. All hardware signals, temperatures, and bus packets shown in the 3D views are deterministic educational simulations.
2. **Bounded Educational RV32I Subset**: The built-in Two-Pass Assembler and Single-Cycle/Pipeline simulators implement the core educational RV32I integer subset (`ADD`, `SUB`, `AND`, `OR`, `XOR`, `SLT`, `ADDI`, `ANDI`, `ORI`, `XORI`, `SLTI`, `LW`, `SW`, `BEQ`, `BNE`, `LUI`, `AUIPC`, `JAL`) with 32-bit word-addressed memory and MMIO at `0x00000100`. Privileged CSRs, virtual memory page tables (`Sv32`/`Sv39`), floating-point extensions (`F`/`D`), and misaligned byte/halfword traps (`LB`/`LH`/`SB`/`SH`) are outside the scope of this introductory DDCA lab.
3. **Educational Silicon Floorplan vs. Commercial Die Photomicrograph**: The 3D CPU silicon die view represents a clean pedagogical floorplan (Control Unit, ALU Array, Register File, L1/L2/L3 Cache, Memory Controller) so students can visually connect Modules 1–6. It is not a transistor-level GDSII layout of a commercial processor.
4. **Separate 8-Bit Gate-Level Microcomputer (`logic-microscope.html`)**: The supplementary gate-level microscope models a custom 8-bit accumulator/register microcomputer so students can inspect individual full-adder XOR/AND/OR gates in 3D; it is intentionally kept separate from the 32-bit RV32I processor lab.
5. **Stylised 3D hardware**: The 3D computer is a procedural, educational model rather than a teardown of any real product. Dimensions are plausible (ATX-class board, LGA-style package, DDR5 UDIMM, M.2 2280) but part names and the die floorplan are illustrative.
6. **WebGL 2 required for the 3D views**: The custom renderer needs WebGL 2 with `EXT_color_buffer_float` for HDR (it falls back to 8-bit if missing). Very old GPUs or locked-down browsers show a notice instead of the 3D scene; the rest of the course is unaffected. Rendering is quality-capped to ~3.2 M pixels for performance on 4K displays.
7. **Legacy standalone page**: `logic-microscope.html` still loads Three.js and Tailwind from CDNs and therefore needs internet access. `cpu-lab.html` and `learn.html` now redirect into the main app.
